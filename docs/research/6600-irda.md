# Nokia 6600 IrDA: the SIR UART behind euart1.pdd

Firmware NHL-10 V 05.53. What the IrDA stand-in (`src/qemu-ngage/hw/arm/ngage_sir.c`, hack H-nhl10-sir) is built on.
**[V]** read in the firmware or seen in a run, **[I]** inferred. Addresses: ROM virtual (0x5xxxxxxx), physical (0x0Cxxxxxx).

## Result (2026-11-26)

Two `-M nokia6600` phones joined by one UDP link beam to each other: phone A (Calendar, Options, Send, Via infrared)
discovers phone B (Infrared on), both switch the link to 115200 baud, and B's Inbox gets "Infrared device: Calendar
entry" with A's memo [V run]. Usage: docs/eka1-ngage.md "Infrared".

## The stack

- `irda.esk` [V]: protocols irmux and tinytp from `irda.prt`; `irPhysicalComPort= 1`, `irBaud= 115200`,
  `irSupportedBauds= 63`, `irPod= jeteye7401` (an external-dongle setting: the built-in transceiver ignores it [I]).
- COMM::1 is `euart1.pdd`, whose panic category is **"SIR.PDD"** [V]: on the 6600 this PDD drives only the IrDA
  UART. The N-Gage NEM-4's euart1.pdd (3664 bytes, "Comm.PDD" only) is a plain UART driver for the same block.
- SIR means the UART sends plain bytes; IrDA framing (BOF 0xC0, EOF 0xC1, 0x7D escapes, CRC) and IrLAP are done by
  `irda.prt` in software [V: the first frames on the line are IrLAP XID discovery frames ending with the device name
  "Nokia 6600"]. So the byte stream on a QEMU chardev is the raw SIR stream.

## Registers (16-bit, through ekern's accessors: read 0x50339428, write 0x50339538, modify 0x50339318; the
offsets are 0x0C000000-relative)

| Address | Use by the driver [V] | Meaning [I] |
|---|---|---|
| 0x0C15000C | W 0x28 at TX start, 0x10 after TX, 0x38 on stop, 0x20 in the ISR | CTSI FIQ: disable bits |
| 0x0C15000E | W 0x128 at power-up, 0x10 at TX start, 0x28 after TX, 0x20 in the ISR / poll timer | CTSI FIQ: enable bits |
| 0x0C1500BA | R in the ISR; W 0x128 / 0x10 after handling | CTSI FIQ status, write 1 to clear: 0x08 RX data, 0x10 TX done, 0x20 RX activity, 0x100 RX end |
| 0x0C150510 | W 3, 8 (create), 4 (configure), 0x200 (power-up) | control |
| 0x0C150512 | W 0x410 (create) | line set-up |
| 0x0C150514 | R bit 2 before every reconfigure (1000 tries); R bit 0 after each RX byte (-> 0x20000000 flag to the LDD) | status: TX empty; RX error |
| 0x0C150516 | W 1 (create), 0 (after a baud change) | |
| 0x0C150518 | W a baud code (below) | divisor |
| 0x0C15052C | W 0x13 before a baud change | mode |
| 0x0C15053A / 0x0C15053C | W 2 on stop / on power-up | receiver off / on |
| 0x0C150554 | W 0 at create; then TX bytes, byte in bits 15-8 | TX data |
| 0x0C150556 | R until 0x0C150562 reads empty, byte in bits 15-8 | RX data |
| 0x0C15055A | W 0xF at TX start, then n-1 before n TX bytes (up to 16) | TX count |
| 0x0C15055C / 0x0C150562 | R: empty when bits 7-4 == bits 3-0 | TX / RX FIFO pointers |
| 0x0C150560 | W 0 (power-up), 7 (RX interrupt with 0x108), 0x10/0x20/8 | RX control |
| 0x0C14F008 | modify: bit 4 set at TX start, cleared after the last burst | transceiver LED power (left to the catch-all) |
| 0x0C15004A/4C, 0x0C15056A/6C | W 8 / 0x1E / 0x3C / 0x40 at create and TX start | pin set-up (catch-all) |

Baud codes (configure 0x503E5D48, switch on the TBps value) [V codes]: 1200 0x254A, 2400 0x22A5, 4800 0x8152,
9600 0x40A9 (also the default), 19200 0xA054, 38400 0x602A, 57600 0x401C, 115200 0x200E. The low bits are a divisor
of about 1.6 MHz / baud [I].

Half duplex [V]: a TX burst disables the RX bits (0x28) and enables TX done (0x10); when the LDD has nothing more,
the ISR disables 0x10, waits for the FIFO to drain, clears 0x0C14F008 bit 4 and enables 0x28 again.

## Interrupt

The PDD binds by name, `Interrupt::Bind("FiqCTSI_FIQ")` [V: the descriptor at 0x503E652C]. In ekern's FIQ name
table (FiqTimer0 = 0, ...) FiqCTSI_FIQ is index **26** [V]; the handler table at 0x80000B80 had the SIR ISR object
at index 26 [V run]. The board's controller mirrors sources 0-31 into bank 3 (FIQ), so the model raises source 26.

The FIQ dispatcher (ekern 0x503112B4) first reads 0x0C120050: any of bits 0-2 set means a special cause, which it
acknowledges (writing the value back) and handles (bit 1: the kernel's own start-up object in 0x8000001C, created at
0x503110A4, passed to 0x503361D8) **instead of** dispatching bank 3 [V]. The kernel writes 7 there at start-up
(0x503110AC) [V]. The board's catch-all kept the 7, so the first FIQ through the dispatcher looped for ever (the
phone froze as soon as IrDA started). Nothing on the board raises these causes, so the word now reads 0 and writes
do not stick (H-upp-fiq-status). The flash driver's FIQ (timer 3) evidently does not use this dispatcher [I]: boots
and flash writes worked both with the stuck 7 and with 0.

## Not modelled

The RX activity/end bits (0x20, 0x100): the driver's 20 ms poll timer (0x503E6160 -> 0x503E60B4) drains the FIFO
without them. Receive errors, the transceiver's own echo, pulse timing (3/16 bit). Other phones with a "SIR.PDD"
of the same size (7650, 3650/3660, 3230, 6260, N-Gage QD) are not checked.
