# Real modem vs fake modem: what the N95's own modem firmware answers (recorded 2026-11-22)

How: three `sydb start --modem real` sessions (offline seed boot; 4 min idle; factory-fresh first boot, eleven
apps, the profile list, Switch off), no SIM. `tools/cmt/isirecord.py LOG...` pairs every phone request with the
real modem's answers (`<session>/modem/access.log`) and sends the same request to the fake modem core as the N95
runs it in table mode (tests/modem_core_harness.c with the N95's board config and layered table). Rerun it on new
recordings to find more gaps; `--emit` proposes `reply` lines. Serial-number/IMEI answers are never written.

## What was adopted

- **Never answered in table mode** (a table boot's `tools/isi.py log` listed exactly these): INFO 1B 0B,
  PN_CALL 01 AA, 02 06, 02 25, GPDS 31 06, and the route release 77 07, now answered with the real modem's
  bytes in platform/isi/replies-bb5.txt (`# on: n95 (real modem fw)`). A table boot now has 0 unanswered requests.
  77 07: the real modem sends 08 {00 55} and then 09 {00 00}; the table gives the 09 only, as for 77 01 (Aamm
  treats 08 as a no-op and 09 as "done").
- **09 DE with no card**: DF {01 FB} (the N95's own form, as its other no-card SIM reads); a declared conflict
  in models/nokia-n95-8gb-rm320/isi-replies.txt with the N8's long form.
- Regression tests: tests/modem_unit_test.py ModemCoreReplies `test_recorded_*`; the tool: tests/isirecord_test.py.

## Differences kept on purpose

- **State, not protocol**: the recordings are an offline phone without a SIM and without per-phone data. MTC
  15 02/15 16/15 01, NET 0A 00/0A 36 (registration, RAT), 19 0A (time), 23 04 (permanent data: the stand-in PMM
  lacks the record, "11"), 35 02 {01 00} (self-test list) answer from that state; table mode plays a phone in
  NORMAL, and its MTC answers are code in syborg_modem_core.c that follows MTC_STATE_REQ.
- **SIM "data not available"**: 09 1D/1F answer `24` in table mode where the N95 modem says `FB`. `24` is a
  deliberate fix for the 5800 (its TSY retried for ~10 s on another status; docs/devices/nokia-5800-rm356/
  settings-delay.md). With `FB` the N95's TSY retried READ_IMSI every 0.5 s (32 times) while apps started.
- **Audio 0B**: the real modem's 0B 00 answers protocol version 03/04 and the phone then sends version-4 requests
  (0B 14/19 with a device byte, answered with sub-blocks); table mode answers version 01 and the core's audio code
  (key tones through syborg-snd, `modem_audio_params`) parses the version-1 form. Moving table mode to version 4
  means rewriting that code; not done.
- **Product profile / identity**: 1B 2E (the short form protects SAServer's 128-byte buffer), 1B 02 PP values,
  1B 00 serial (board config), DB 01 name table: table mode keeps its own values.
- **Echo vs short**: light 3A 20/22/24/28 and some others: the real modem answers `{00 00}`, table mode echoes
  the request. Both are accepted by the phone; left as they are (the shared table is verified on the N8).
- **Real modem's "not supported"**: 59 42, 1C 2D answer COMMON F0 14/F0 01 on the N95 modem; table mode keeps
  the answers other phones needed.
- Pairing limit: answers are matched by (resource, transaction id, channel); requests that reuse tid 0 (all 77
  requests) can have a late 09 counted under the next request.
