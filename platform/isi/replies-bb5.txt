# Fake-modem canned replies of every BB5 phone (family bb5-s60): one table for all of them
# (layering checked by tools/isi.py lint). A reply to a request a firmware never sends is inert, so the table is
# the union of what each phone needed; `# on:` names where a reply was verified (none = all members).
# Device files (models/<id>/isi-replies.txt) come after this one and are only for true conflicts:
# the same (resource, request) needing different bytes on different phones (none today).
# `tools/isi.py lint` checks the layering.
# Format and names: platform/isi/names.txt, tools/isi.py.
# 1B 2E -> 2F (PP, product profile bits) [V both sides, docs/research/n95-isi-encoders.md 6]: the N95 modem sends
# 138 data bytes, `00 01 F0 00 88 00` (status, 1 sub-block: id16 F000, len8 0x88 = 136, filler) + u32 BE flags + the
# 128-byte PP block. The phone (SAFeatureInfoService FUN_8092313e, ISIMESSAGE type 3 = id16/len8) reads only [10]
# status, [11] nsb, the F000 sub-block, flags [16..19] (0 here), words [20..23] (flag bit 0) and [24..27] (bit 1):
# 18 data bytes, a whole 16-byte sub-block. The 2026-11-18 hang with the full form was our ISC stand-in answering
# KErrOverflow instead of the real driver's KErrNoMemory (fixed: iscrx.h, H-isc-rx-overflow); the short form keeps
# every reply within 118 data bytes. The old 16-byte form had the length in the filler byte (`00 10`).
reply 1B 2E 2F len=18 00 01 F0 00 10 00                   # PP: product profile bits, sb F000 len 16, flags 0 (features 3/4 off) [V layout, I values]
reply 0A 0B 0C 00 01 04 04 00 00                          # NET_RSSI_GET

reply C8 36 37 00 01 2C 04 01 00                          # NET_RAT on PN_MODEM_NETWORK (Symbian^3 TSY): unanswered, Anna's connection monitor waited on its ETel request forever and the home screen on it
reply C8 00 01 00 01 00 04 06 00                          # NET_MODEM_REG_STATUS_GET on PN_MODEM_NETWORK: OK, NET_REG_INFO_COMMON, NOSERV_NOSIM (6), as 0A 00 (docs/devices/nokia-n95-8gb-rm320/n95-isc-isi-protocol-2.md 3.1.7)

# sub-block per set bit, in bit order, {02 00} for mask 0 or an unknown bit [V] docs/research/n95-isi-encoders.md 5. These lines are the value pool
